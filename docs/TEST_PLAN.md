# AgentWeave 全功能测试与验收文档

> 目标：覆盖平台当前涉及的对话、模式、模型、Skill、MCP、知识库、记忆、文件产物、运行控制、自动化能力，以及 builtin / Codex / Claude Code 执行引擎与容器沙箱隔离。
>
> 测试地址：<http://127.0.0.1:8000/>
> 记录方式：每个用例执行后填写“结果”和“备注”，不要只看最终答案，还要检查执行过程、节点明细、调用明细和下载文件。

## 1. 测试约定

- `round1/round2/...` 表示同一个对话中的连续消息；每轮都要确认上下文是否被正确继承。
- 每个任务至少检查：目标理解、计划节点、Skill/MCP 子节点、模型节点、最终验收、对话答案和任务状态。
- 结果标记：`[ ] 未测`、`[x] 通过`、`[!] 部分通过`、`[失败]`。
- 真实模型、联网搜索、远程 MCP 和远程安装需要提前配置密钥与网络开关；没有配置时应验证平台是否给出友好提示，而不是把内部堆栈展示给用户。
- 文件测试使用临时文件，测试结束后删除测试产物或单独标记为测试文件。

## 2. 测试前置条件

### 2.1 服务和页面

- [ ] 启动服务，访问首页不是 `file://` 地址。
- [ ] 访问 `/api/health` 返回 `ok: true`。
- [ ] 刷新页面后能看到已保存的模型、Skill、MCP、项目和历史任务。
- [ ] 浏览器控制台无 JavaScript 错误。
- [ ] 侧边栏可以展开、收起，所有功能入口可点击。

### 2.2 模型

准备两个模型选项：

1. 内置“离线确定性模型”，用于无网络流程和错误恢复。
2. 一个已配置并通过连接测试的 OpenAI-compatible 模型，用于复杂创作、工具调用和真实流式输出。

分别测试：环境变量 API Key、直接 API Key、错误 Key、空 Base URL、非法高级 JSON、重复模型 ID、停用模型和删除模型。

### 2.3 能力和测试资料

准备以下资料：

- `sample.txt`、`sample.md`、`sample.csv`、`sample.json`
- 一个包含段落和表格的 `sample.docx`
- 一个包含多个工作表的 `sample.xlsx`
- 一个包含文字和表格的 `sample.pptx`
- 一个可搜索文本的 `sample.pdf`
- 一个简单的 `sample.html`
- 一个测试 Skill ZIP（只包含一个 `SKILL.md`）
- 一个只读 MCP/HTTP 工具配置，以及一个缺少必填参数的工具配置

## 3. 普通模式

普通模式由一个智能体完成任务，会自动匹配已启用的 Skill 和 MCP。以下用例不仅测试“能不能回答”，还测试上下文是否正确、是否调用了不相关工具。

### 3.1 天气上下文、澄清和目标切换

#### 用例 N-01：天气多轮续问

- [ ] `round1`：`今天天气怎么样？`
- [ ] 如果平台询问城市，`round2`：`宁波`
- [ ] 如果第一轮已识别城市，直接记录平台是否正确识别。
- [ ] `round3`：`明天呢？`
- [ ] 预期：复用宁波，调用 `weather.forecast`，返回明天日期和天气，不重新询问城市，不走离线泛化回答。
- [ ] 检查：对话答案、MCP 子节点、工具参数中的 `city/day`、最终验收。

#### 用例 N-02：天气结果切换为旅行计划

- [ ] 在 N-01 对话继续发送：`帮我写个旅行计划，明天从杭州自驾去宁波的，然后给这个旅行计划生成一个 PPT 和 Word 文档，供我下载。`
- [ ] 预期：建立新的目标合同，停止沿用旧天气目标；只在计划明确需要时调用天气，不得因为历史天气上下文误调用天气工具。
- [ ] 预期产物：`pptx` 和 `docx` 均生成，回答中有下载入口，任务详情和“产物”页均可下载。
- [ ] 检查：旅行路线、时间安排、风险提示、文件内容与当前任务一致。

#### 用例 N-03：天气参数缺失与取消

- [ ] `round1`：`查一下天气。`
- [ ] 预期：只用一句友好问题询问城市或地区，不展示模型思考过程。
- [ ] `round2`：`算了，不查了。`
- [ ] 预期：任务可以结束或取消，不再调用天气工具。

### 3.2 Markdown 和连续文档创作

#### 用例 N-04：学习文档与格式复用

- [ ] `round1`：`帮我写个 Transformer 的入门学习文档，Markdown 格式给我。`
- [ ] 预期：正文按 Markdown 渲染，生成可下载 `.md` 文件。
- [ ] `round2`：`按照上面的文档格式和结构，帮我写一份关于 Codex 软件平替开发的项目需求文档。`
- [ ] 预期：继承结构和格式，不继承无关事实；生成新的 Markdown 文档，标题、目录、章节层级清晰。
- [ ] 打开 Markdown 产物预览，确认不是源码整页展示；代码块内部显示源码属于正常情况。

#### 用例 N-05：普通问答和上下文边界

- [ ] 发送：`解释一下 Transformer 的自注意力机制。`
- [ ] 发送：`用上面的内容举一个电商推荐的例子。`
- [ ] 新建对话后再次发送：`上面的内容是什么？`
- [ ] 预期：同一对话能继承上下文，新对话不混入旧对话正文；用户级/工作区级记忆按配置生效。

### 3.3 文件上传和资料处理

- [ ] 分别上传 TXT、MD、CSV、JSON、DOCX、XLSX、PPTX、PDF、HTML。
- [ ] 发送：`总结我上传的资料，列出关键结论、风险和待办。`
- [ ] 预期：右侧显示附件已进入上下文；回答引用的内容确实来自附件。
- [ ] 上传超大文件、扫描 PDF、加密文件和不支持的二进制文件。
- [ ] 预期：给出明确的解析限制或失败原因，不伪造“已读取全部内容”。
- [ ] 测试 10 个以上附件、超长正文和重复上传，确认限制和提示一致。

### 3.4 常见文档产物

对同一份输入资料分别发送以下任务，并检查预览、下载、MIME 类型、文件名和内容：

- [ ] `生成 Word 报告（DOCX），包含摘要、风险表和行动计划。`
- [ ] `生成 Excel（XLSX），包含原始记录、汇总指标和异常项。`
- [ ] `生成 PPT（PPTX），每页一个主题，并提供下载。`
- [ ] `生成 Markdown 文档，并打开预览。`
- [ ] `生成 HTML 页面，并打开安全预览。`
- [ ] `生成 PDF 报告，并打开浏览器预览。`
- [ ] 每种格式都确认：任务验收通过后才发布；文件可下载；重新打开任务后仍可下载。
- [ ] PPTX 未配置 Node.js/Artifact Tool 时，预期为明确的能力不可用提示，不生成损坏文件。

### 3.5 Skill 能力

- [ ] 在“技能中心”手动创建一个“会议纪要 Skill”，保存并启用。
- [ ] 上传 `SKILL.md` 安装；上传 ZIP 安装；使用 HTTPS 直链安装。
- [ ] 发送：`安装 Skill <直链>`，确认任务进入安装确认卡片，点击确认后完成安装。
- [ ] 发送：`查看已安装技能`，确认对话返回名称、ID、启用状态；“技能中心”清单一致。
- [ ] 发送一个能命中该 Skill 的任务，确认右侧显示 Skill 子节点。
- [ ] 测试缺少依赖 MCP、Skill 被停用、ZIP 多根目录和目录穿越包，确认友好报错并且不会部分安装。
- [ ] 测试任务能力不足时的市场推荐：确认推荐原因、安装前需要用户确认、拒绝后不会自动安装或反复推荐。

### 3.6 MCP 和工具

- [ ] 创建并保存一个本地 stdio MCP，连接并同步工具。
- [ ] 导入 MCP JSON 文件、HTTPS JSON 直链和 `mcpServers` 格式配置。
- [ ] 发送：`安装 MCP <直链>`，确认安装前有交互，安装后在“工具接入”可见。
- [ ] 发送：`查看已安装 MCP`，确认服务名称、启用状态和工具清单。
- [ ] 调用一个只读工具，检查参数、工具结果和耗时明细。
- [ ] 调用缺少必填参数的工具，预期显示简短的参数提示，不展示内部思考过程。
- [ ] 测试服务未启用、Schema 错误、网络白名单拒绝、权限拒绝和工具超时。
- [ ] 预期：错误归类为“工具服务调用失败”或“工具调用未完成”，对话区和执行过程都能看到。

### 3.7 联网搜索和天气联网

- [ ] 关闭出站网络，发送：`搜索今天的 AI 行业新闻并附来源链接。`
- [ ] 预期：说明联网能力未开启，不调用外部服务。
- [ ] 开启出站网络、搜索开关和供应商 Key 后重复测试。
- [ ] 预期：显示搜索工具子节点、标题/URL/摘要，并能区分搜索结果和模型总结。
- [ ] 测试“最新资料”“新闻”“联网搜索”等触发词，以及明确要求“不联网”的反向约束。
- [ ] 关闭搜索 Key 但保留天气能力，确认天气和搜索能力的错误提示不同。

### 3.8 运行控制、实时输出和错误

- [ ] 发送一个需要 5 秒以上的复杂任务，观察回答增量、计划节点和子节点是否实时更新。
- [ ] 展开大节点，确认能下钻到 Skill、模型、MCP 和具体工具。
- [ ] 运行中追加要求，确认旧生成停止，新目标/计划版本被记录。
- [ ] 运行中点击“取消”，确认任务停止且不发布半成品答案。
- [ ] 对失败任务点击“重试”，确认产生新的运行尝试，历史记录保留。
- [ ] 从检查点恢复，确认恢复尝试和节点状态可追踪。
- [ ] 模拟模型网络失败、工具失败和参数缺失。
- [ ] 预期：对话区出现红色错误卡片；模型错误、工具错误、任务错误使用不同的用户可读文案；不显示堆栈、路径、Token 或内部提示。
- [ ] 刷新页面或重新打开历史失败任务，确认错误卡片仍存在。

### 3.9 对话内安装、启用和使用能力

这些用例专门验证“安装动作”和“业务任务”不会互相吞掉。安装前必须有明确的用户确认；未确认前不得写入已安装清单，也不得偷偷调用待安装的能力。

#### 用例 N-06：通过对话安装 Skill，并在同一任务中继续执行

- [ ] 新建对话，发送：`帮我找一个适合生成项目需求文档的 Skill，如果没有就推荐市场上的。`
- [ ] 预期：平台先说明缺少的能力、推荐的 Skill、来源、版本、用途和权限范围，显示“安装/暂不安装”交互，不直接安装。
- [ ] 点击“安装”，确认任务从 `waiting_approval` 恢复执行；安装事件包含 Skill ID、版本和校验摘要。
- [ ] 预期：安装完成后不要求用户重新复制原问题，原任务自动继续，并生成一个 Markdown 或 Word 项目需求文档。
- [ ] 检查：技能中心出现该 Skill；执行明细包含“安装 Skill”和“调用 Skill”两个不同节点；安装前没有调用该 Skill。

#### 用例 N-07：拒绝、取消和恢复 Skill 安装

- [ ] 对同类任务选择“暂不安装/拒绝”，确认任务继续时使用现有能力或明确说明能力不足。
- [ ] 在审批卡片出现后刷新页面、关闭再打开历史任务，确认审批状态仍然存在，不能重复创建多张审批卡片。
- [ ] 在审批状态点击“取消任务”，确认 Skill 未进入已安装清单，原任务没有半成品产物。
- [ ] 对可恢复任务点击“恢复”或重新发送原任务，确认可以再次发起安装确认；旧的拒绝记录不被伪装成已批准。

#### 用例 N-08：通过对话安装 MCP，并在同一会话中调用

- [ ] 准备一个只读的市场 MCP 或本地 MCP 配置，发送：`安装这个 MCP：<名称或链接>`。
- [ ] 预期：显示服务名称、来源、工具清单、所需环境变量、网络/文件权限和风险提示；用户批准前不启动进程、不同步工具。
- [ ] 点击批准后，确认“工具接入”出现服务且状态为已启用，工具 Schema 能正常同步。
- [ ] 继续发送：`用刚安装的工具读取测试资料，列出三条关键结论。`
- [ ] 预期：同一会话自动使用刚安装的 MCP；执行过程依次出现 MCP 安装、工具同步、参数校验、工具调用、结果整理和最终验收。
- [ ] 检查：工具调用参数与 Schema 一致，工具结果进入上下文，回答不把安装日志或隐藏思考当成正文。

#### 用例 N-09：直接查询和核对已安装能力

- [ ] 发送：`查看已安装技能`，确认回答中的名称、ID、版本、启用状态与技能中心一致。
- [ ] 发送：`查看已安装 MCP`，确认回答中的服务名称、类型、启用状态和工具数量与工具接入页一致。
- [ ] 停用一个 Skill 或 MCP 后重复查询，确认清单仍可见但状态为已停用；重新执行命中任务时不得调用它。
- [ ] 重新启用后重复任务，确认恢复调用且不会创建重复安装记录。

#### 用例 N-10：本地创建工具、参数缺失和友好补充

- [ ] 在“工具接入”创建一个本地只读工具，定义一个必填参数（例如 `file_id` 或 `city`）和一个可选参数。
- [ ] 通过对话发送一个故意缺少必填参数的任务。
- [ ] 预期：对话中只显示“还需要提供 XX 参数”的友好提示，不能输出模型思考、完整 Schema、堆栈或内部提示。
- [ ] 补充参数后继续原任务，确认不需要重新描述完整目标；工具调用参数完整且结果被验收节点引用。
- [ ] 检查参数错误、权限错误和工具业务错误使用不同的错误标题，均能在对话区看到。

#### 用例 N-11：Skill/MCP 安装失败的原子性

- [ ] 分别测试：无效链接、网络被关闭、主机不在白名单、包超限、ZIP 多根目录、目录穿越、缺少 `SKILL.md`、MCP Schema 非法、命令不存在。
- [ ] 预期：对话显示可行动的失败原因和下一步；不留下半个目录、半条服务配置、错误的已安装状态或伪造的“安装成功”。
- [ ] 重新打开技能中心和工具接入，确认失败项不显示为已启用；检查任务事件中只有一次失败结论，不重复执行安装。

### 3.10 复杂混合任务：一个对话中连续更换目标

以下场景用于模拟真实用户，不允许通过“每个问题新建一个对话”规避上下文问题。每轮都记录当前目标合同、计划版本、已安装能力和实际调用。

#### 用例 N-12：附件总结 → Markdown → Word/PPT → 安装美化 Skill → 重新生成

- [ ] `round1`：上传 `sample.docx` 和 `sample.xlsx`，发送：`先基于附件总结项目进展、风险和待办，不能补充附件之外的事实。`
- [ ] `round2`：`把上面的总结整理成结构清晰的 Markdown 文档，并提供下载。`
- [ ] `round3`：`按照同一份事实再生成 Word 和 PPT，PPT 要有封面、目录、风险页和总结页。`
- [ ] `round4`：`PPT 视觉效果还不够好，请推荐一个市场上的 PPT 美化 Skill，先不要安装。`
- [ ] 预期：只推荐不安装，给出推荐理由和待确认按钮；旧的文档目标仍保留，不能跳去天气或无关工具。
- [ ] `round5`：点击安装后发送：`按刚安装的 Skill 重新生成 PPT，并保留原来的事实和章节结构。`
- [ ] 预期：Skill 安装完成后自动进入新计划版本；重新生成的 PPT 与附件事实一致；旧 PPT 保留为历史版本，新 PPT 单独可下载。
- [ ] `round6`：`把 PPT 中的风险和待办再整理成 Excel。`
- [ ] 预期：只生成 XLSX，不重复调用 PPT 生成器，不丢失当前会话的附件事实。
- [ ] 检查：每次目标切换都有目标确认或计划更新；执行明细可下钻到附件上下文、Skill、MCP、模型和产物验收。

#### 用例 N-13：缺少工具 → 市场推荐 → 用户确认 → 原任务续跑

- [ ] `round1`：`读取我上传的 CSV，计算每个类别的数量、金额合计和异常项，并生成 Excel。`
- [ ] 在平台没有相应分析工具时，预期出现能力缺失卡片和市场推荐，不直接调用天气或其他不相关工具。
- [ ] `round2`：用户选择“查看推荐”，确认推荐项的权限、来源、版本、参数和风险。
- [ ] `round3`：用户点击“安装并继续”。
- [ ] 预期：安装前任务停在审批节点；批准后原任务继续，不需要重新发送 CSV 处理目标；最终生成 XLSX 并完成格式/下载验收。
- [ ] 如果用户选择“只安装不执行”，预期：服务安装成功，但原任务明确保持待执行或结束，不擅自执行文件分析。

#### 用例 N-14：天气上下文后转为非天气文档任务

- [ ] `round1`：`今天天气怎么样？`
- [ ] 如需城市，`round2`：`宁波`；再发送 `明天呢？`
- [ ] `round3`：`把刚才的天气信息整理成一份出行提醒 Markdown，不需要再查天气。`
- [ ] 预期：第三轮只使用已有天气结果生成 Markdown，不再次调用天气工具，也不补造实时数据。
- [ ] `round4`：`现在改成写一份 Transformer 入门文档，和天气无关。`
- [ ] 预期：创建新的目标合同和计划，天气上下文不进入正文；生成文档时只匹配文档相关 Skill。

#### 用例 N-15：联网搜索失败但文档任务继续

- [ ] 关闭联网搜索，发送：`搜索最近的 AI 行业动态，并整理成带来源链接的 Markdown 报告。`
- [ ] 预期：先明确搜索能力不可用，不伪造新闻、日期或来源；若用户同意离线模式，生成“待补充来源”的结构化草稿。
- [ ] 重新开启搜索后点击“重试”，确认只重试搜索节点及其下游节点，不重复安装 Skill/MCP、不重复生成无关产物。
- [ ] 检查：失败原因在对话卡片中出现，任务状态和运行尝试清晰可见。

#### 用例 N-16：普通模式与专家模式交错

- [ ] `round1` 在普通模式：`解释一下 Transformer 的注意力机制。`
- [ ] 切换专家模式后 `round2`：`请由产品、技术和安全专家评审一个基于 Transformer 的企业知识库方案，并输出风险清单。`
- [ ] `round3` 切回普通模式：`把专家结论整理成 Word 和 PPT。`
- [ ] 预期：模式切换只影响下一条消息；专家任务有成员和主管节点，普通模式文档任务不重复启动专家团；第三轮能引用已验收的专家结论。
- [ ] 如果专家任务仍在运行时发送第三轮，预期：平台提示等待/追加指令，不创建竞态任务或混用未验收成员输出。

#### 用例 N-17：工具参数错误 → 补参 → 产物验收

- [ ] 发送：`用本地报表工具生成宁波本周销售汇总，并导出 Excel。`，故意不提供工具要求的日期范围。
- [ ] 预期：计划停在参数补充节点，提示“还需要日期范围”，不执行工具、不生成空 Excel。
- [ ] `round2`：`时间范围是 8 月 18 日到 8 月 24 日，只统计已支付订单。`
- [ ] 预期：恢复原计划，调用工具前再次复核目标和参数，工具返回后生成 XLSX，并在最终验收中确认文件非空、表头和下载链接。
- [ ] 检查：参数补充内容可追溯到同一任务，不能被下一条无关消息覆盖。

#### 用例 N-18：复合请求取消和恢复

- [ ] 发送：`安装一个适合 PPT 的 Skill，然后基于附件生成 PPT 和 Word，最后把结论写进 Excel。`
- [ ] 在安装审批前点击取消；预期：没有安装、没有生成三个文件、没有发布半成品。
- [ ] 重新发送同一任务并批准安装，在 PPT 生成过程中点击取消；预期：保留安装成功记录，但未验收的产物不发布；任务状态为已取消并说明中断节点。
- [ ] 点击恢复或重试，预期：从最近安全检查点继续，只执行尚未完成的交付，不重复安装或覆盖已发布版本。

#### 用例 N-19：对话配置内置 PPT 工具与复合请求边界

- [ ] 新建对话发送：`直接给我配置好 PPT 工具。`
- [ ] 预期：作为平台配置指令直接处理，不依赖在线模型；返回已启用的生成器、是否需要 Docker/Node.js、当前生效状态和下一步使用方式。
- [ ] 检查：能力页的 `pptx_configured` 变为 `true`，`.env.local` 或等效配置可持久化，任务事件不泄露本机绝对路径。
- [ ] 在同一对话发送：`根据上面的内容生成一份 3 页 PPT，并提供下载。`
- [ ] 预期：进入正常计划，匹配 PowerPoint Skill，调用文档生成 MCP，产物通过格式和下载验收；不能因为上一轮是平台指令而跳过生成。
- [ ] 另测复合输入：`配置好 PPT 工具后，再生成一份旅行计划 PPT。`
- [ ] 预期：不能只返回“配置完成”而吞掉后半句；应继续完成旅行计划 PPT，或明确询问缺少的旅行参数。
- [ ] 如果用户指定外部 Artifact Tool，预期：说明需要用户提供 Node.js/入口路径或打开配置向导，不得猜测路径、自动执行未知脚本或把外部工具伪装成已安装。

#### 用例 N-20：本地/远程 HTTP 工具配置与边界

- [ ] 在“工具接入”创建一个本地 HTTP 只读工具，填写名称、Base URL、路径、请求方法、参数 Schema 和超时，保存后执行连接测试。
- [ ] 预期：连接测试结果、工具清单和启用状态可见；模型只能看到脱敏后的配置，不显示 API Key、内部路径或完整请求头。
- [ ] 关闭远程 HTTP 工具开关后，尝试添加公网地址，预期在保存或调用前被拒绝，并说明需要开启的能力和白名单要求。
- [ ] 开启远程能力但使用未加入白名单的主机，预期同步/调用被策略阻断，不应静默改用其他工具。
- [ ] 通过对话发送：`查看当前可用的 HTTP 工具并调用只读查询。`
- [ ] 预期：只匹配已启用且允许当前 Agent 使用的工具；执行明细包含工具 ID、参数校验、耗时、结果摘要和最终验收。
- [ ] 删除或停用该工具后重试同一任务，确认不会继续使用旧缓存，也不会将停用工具显示为调用成功。

### 3.11 故障恢复与边界组合场景（补充）

前面的用例已经覆盖正常业务链路；本节专门补充最容易让用户误以为“平台没反应、串上下文或重复执行”的边界。它们不要求每次冒烟都执行，发布前或涉及运行时改动时优先执行。标记为“手工”的项目不能只用单元测试替代。

#### 用例 N-21：当前模型不可用 → 对话区报错 → 切换模型重试

- [ ] 配置一个连接测试失败或已停用的模型，将它选为当前模型，发送：`请回复：模型连通性测试。`
- [ ] 预期：发送后立即出现“正在处理”或明确失败状态；对话区展示可行动的模型错误（连接失败、未就绪或网络未开启），不能静默无回复，也不能展示堆栈、Key、内部 URL 或隐藏思考。
- [ ] 切换到已通过连接测试的模型（或内置离线模型），点击“重试”或重新发送同一目标。
- [ ] 预期：新运行绑定新模型并完成；旧失败运行保留为失败记录，不与新答案拼接，不重复调用旧模型。
- [ ] 再刷新页面，确认模型选择和任务运行记录仍显示正确的模型 ID。
- [ ] 自动化已有模型配置/错误接口覆盖；本用例仍需手工验证“工作台选择器 → 对话错误 → 切换后重试”的完整路径。

#### 用例 N-22：网络/模型不可用 → 对话区明确提示 → 检查后重试

- [ ] 关闭出站网络、移除模型主机白名单，或选择连接测试失败/已停用的模型，发送一个普通问题。
- [ ] 预期：对话区明确显示“模型不可用、网络未开启、连接失败”等可读提示，并说明检查配置或切换模型的下一步；不能静默无响应，也不能展示堆栈、Key、内部 URL 或隐藏思考。
- [ ] 切换到已通过连接测试的模型，或恢复网络配置后点击“重试”，确认原目标可以继续完成。
- [ ] 检查任务状态、失败原因和模型 ID 可追溯；失败运行不与重试结果拼接，不生成伪造答案。
- [ ] SSE 事件游标、断点续传和重复事件防护继续由自动化回归覆盖；本轮不要求专门制造真实浏览器断网。

#### 用例 N-23：服务重启 → 运行任务恢复/安全结束

- [ ] 运行一个包含工具调用或产物生成的任务，在安全检查点之后重启本地平台服务。
- [ ] 预期：重新打开任务后，任务不会永久停在“执行中”；平台要么从最近检查点恢复并继续，要么明确显示可恢复/失败节点和下一步操作。
- [ ] 检查已完成的只读工具不会被无条件重复调用，写入型工具和产物发布遵循幂等/验收门禁；恢复后只发布一次最终答案和文件。
- [ ] 若服务在审批等待阶段重启，审批卡片只保留一张，用户拒绝/取消的决定不能被重启覆盖。
- [ ] 自动化已有重启恢复测试；本用例仍需在当前本机服务上实际停启一次，验证页面可观测性和恢复提示。

#### 用例 N-24：同名产物多次生成 → 版本、预览、下载可区分

- [ ] 在同一任务中两次要求生成同名 `项目报告.docx`，第二次只修改一处内容；再分别生成同名 PPT 或 Excel。
- [ ] 预期：每次生成都有独立产物 ID、版本或运行关联，旧文件不可被静默覆盖；列表中能区分生成时间/版本和所属运行。
- [ ] 分别打开预览、下载、刷新页面后重新下载，确认内容与对应版本一致，不能把旧下载链接指向新文件。
- [ ] 取消或验收失败的版本不出现在“可下载/已发布”列表中；删除或停用只影响目标版本。
- [ ] 自动化已有同名文件不可变、路径安全和发布门禁覆盖；本用例补充真实页面上的版本辨识和回读。

#### 用例 N-25：跨工作区/会话的附件、知识库和产物隔离

- [ ] 在工作区 A 上传 `同名资料.md`、建立知识库并生成一份报告；切换到工作区 B，上传同名但内容不同的文件。
- [ ] 在 B 中提问：`总结同名资料并生成报告。`，确认只引用 B 的附件/知识库，不能看到 A 的内容或下载 A 的产物。
- [ ] 新建会话但仍在 B，确认不会自动继承 A 会话的正文、附件和工具结果；切回 A 后才可看到 A 的资源。
- [ ] 使用不同用户或无权项目参数直接请求资源 ID，预期返回统一的无权/不存在提示，不泄露资源是否存在、文件路径或正文片段。
- [ ] 自动化已有工作区与知识库作用域测试；跨会话附件和“同名资源”场景仍需手工补测。对外部署前还必须增加真实登录/RBAC/租户测试。

#### 用例 N-26：重复点击发送/浏览器重试 → 不重复创建任务或产生副作用

- [ ] 在发送一个会生成文件或调用工具的请求时连续点击发送，或让浏览器重复提交同一请求。
- [ ] 预期：平台按幂等键/消息 ID 只创建一个逻辑任务和一个运行；按钮进入发送中/禁用状态，并给出当前运行提示。
- [ ] 检查只调用一次有副作用的工具、只发布一个产物；重连或刷新不重复追加用户消息。
- [ ] 对同一任务点击一次“重试”应产生一个新的明确运行；重复点击重试不能产生多次并行恢复。
- [ ] 自动化已有部分命令/审批/Worker 幂等测试；聊天发送和产物副作用需要手工验证。

#### 用例 N-27：长对话摘要/记忆 → 新目标确认 → 不串入旧事实

- [ ] 在同一会话连续发送多轮资料问答，直到出现会话摘要或上下文压缩；随后发送：`现在改为写一份与前面主题无关的项目方案，不能沿用前面的事实。`
- [ ] 预期：平台先确认新的目标合同/计划，旧目标只作为明确引用时才可使用；新文档不得混入旧资料、旧天气、旧工具结果或旧附件。
- [ ] 发送：`记住：以后文档使用中文。`，再新建会话验证只继承已授权的偏好，不继承旧会话正文和临时工具结果。
- [ ] 检查计划版本、摘要引用、记忆节点和最终验收记录，确认目标确认发生在执行前、输出前又复核一次。
- [ ] 自动化已有上下文、摘要、记忆和目标替换的分散覆盖；本用例用于验证真实长对话中的组合行为。

## 4. 专家模式

### 4.1 专家团准备

- [ ] 创建至少 3 个智能体：产品体验、技术实现、安全审查。
- [ ] 为每个智能体配置不同职责、模型、Skill 和权限。
- [ ] 创建并启用专家团，指定主管、至少两名成员、成员职责、主管汇总要求和验收条件。
- [ ] 禁用专家团后，专家模式应提示“没有可用专家团”，不能静默退回普通模式。

### 4.2 专家协作主流程

#### 用例 E-01：多角度方案评审

- [ ] 切换到专家模式，选择“自动匹配专家团”。
- [ ] 发送：`请从产品体验、技术实现和安全风险三个角度评审这份方案，输出 P0、P1、P2 建议，最后整理统一结论。`
- [ ] 预期：显示专家选择原因、团队成员、并行子任务、成员交付、主管汇总和团队验收。
- [ ] 检查：成员之间上下文隔离；主管能读取成员交付；最终答案合并而不是简单拼接。

#### 用例 E-02：专家模式生成文档

- [ ] 发送：`请由产品、技术和安全专家共同完成 AgentWeave 项目评审，并生成 Word 和 PPT。`
- [ ] 预期：专家汇总通过验收后才发布 DOCX/PPTX；下载区和“产物”页都有文件。
- [ ] PPTX 能力未配置时，其他交付仍可完成，并明确说明 PPTX 不可用原因。

#### 用例 E-03：指定团队和切换模式

- [ ] 在输入区指定一个已启用团队，再发送同一任务。
- [ ] 预期：使用指定团队，不被自动匹配覆盖。
- [ ] 运行中切换普通/专家模式。
- [ ] 预期：只影响下一条消息，当前任务执行器不变。

#### 用例 E-04：成员失败、重试和验收

- [ ] 让一个成员使用错误模型或不可用 MCP。
- [ ] 预期：只标记该成员失败，主管能看到失败原因；允许单独重试成员。
- [ ] 测试成员交付缺少必需关键词、字数不足或文件格式不符。
- [ ] 预期：团队验收不通过，不发布“已完成”的最终交付；修复或重试后可继续。

#### 用例 E-05：专家成员缺少 Skill/MCP 时的统一审批

- [ ] 创建一个只有技术专家可用、产品专家不可用的分析 Skill，另配置一个仅安全专家允许调用的只读 MCP。
- [ ] 发送：`请产品、技术和安全专家联合评审这份系统方案，并分别引用各自需要的能力。`
- [ ] 预期：平台先列出每位成员缺少的能力和推荐项，合并为一次可追踪的审批交互；未批准的成员不能调用未安装能力。
- [ ] 只批准其中一个推荐项，确认只有对应成员恢复，其他成员保持“能力不可用”并向主管报告，不被静默替换为无关 Skill/MCP。
- [ ] 主管汇总必须标注成员能力差异、未完成分工和对最终结论的影响；团队验收不应把缺失成员伪装成已完成。

#### 用例 E-06：专家任务中的安装拒绝与原目标保持

- [ ] 在专家模式发送：`请由安全专家审查附件，并在需要时安装市场上的安全审计 Skill；先给我安装建议。`
- [ ] 预期：先返回建议和权限说明，等待用户确认；产品/技术专家不会被无关拉起，安全专家也不会提前执行待安装 Skill。
- [ ] 选择拒绝后发送：`不安装，使用现有能力完成能完成的部分，并明确局限。`
- [ ] 预期：原专家任务继续，最终答案保留安全审查范围、局限和未完成项；不会循环推荐同一个 Skill，也不会改变为普通模式。

## 5. 模型、权限和网络配置专项

- [ ] 环境变量 API Key：保存模型、重启服务、测试连接、工作台选择并完成任务。
- [ ] 直接 API Key：保存后只显示“已保存”，接口和页面不回显明文。
- [ ] 直接 Key 解密失败或密钥轮换后，显示需要重新配置，不泄露密文。
- [ ] 关闭 `APP_ALLOW_OUTBOUND_NETWORK`：在线模型、天气、搜索、远程 MCP、远程安装均给出对应提示。
- [ ] 配置模型主机白名单：允许的主机可访问，未列入主机被拒绝。
- [ ] 配置 MCP 服务白名单：远程服务可同步，未授权域名被拒绝。
- [ ] Agent 的 `allowed_tools`、`denied_tools`、`read_only`、调用次数和超时限制生效。
- [ ] Policy 要求审批时，任务停在审批节点；批准和拒绝都会写入事件。

## 6. 知识库、记忆和项目

### 6.1 知识库

- [ ] 创建知识库、上传文档、建立索引、查看文档和分片数量。
- [ ] 用关键词检索，确认返回文档名、片段编号和命中数量。
- [ ] 在对话中问一个知识库内问题，确认执行过程显示知识引用。
- [ ] 停用知识库或文档后再次提问，确认不会继续注入已停用内容。
- [ ] 测试不同项目之间的知识库隔离。

### 6.2 记忆和上下文

- [ ] `记住：以后评审结果都用中文，并按 P0、P1、P2 排序。`
- [ ] 在同一对话和新对话分别验证记忆作用范围。
- [ ] `查看记忆`、编辑、停用、删除和 `忘记：...`。
- [ ] 验证新任务目标优先于普通偏好，不能被记忆改写成另一个任务。
- [ ] 验证对话摘要生成后，后续任务仍能引用关键事实。

### 6.3 项目工作区

- [ ] 创建项目、切换项目、停用项目、刷新页面后保持当前项目。
- [ ] 验证项目之间的 Skill、MCP、知识库、记忆和任务不可越权混用。
- [ ] 上传资料、生成产物、运行任务后，确认所属项目正确。

## 7. 自动化任务

- [ ] 创建自动化，先手工试运行一轮，再启动调度。
- [ ] 测试固定间隔、Cron、单次时间和签名 Webhook。
- [ ] 配置最大轮数、连续失败熔断、每轮重试次数和退避时间。
